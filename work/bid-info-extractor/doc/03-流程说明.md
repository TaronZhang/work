### 2.2 飞书日历提醒

```
 用户点击「创建日历提醒」
  │
  ▼
  create-event API
  │
  ├─ 1. 检查飞书配置 (feishu_app_id/secret)
  │
  ├─ 2. 获取 tenant_access_token (缓存 2h)
  │     POST /open-apis/auth/v3/tenant_access_token/internal
  │
  ├─ 3. 获取日历列表
  │     GET /open-apis/calendar/v4/calendars
  │
  ├─ 4. allocate_calendar_slot(deadline, busy, existing)
  │     │
  │     ├─ remind_date = deadline - 4 days
  │     ├─ weekday_adjust (周末前移)
  │     │
  │     ├─ for backtrack in 0..3:
  │     │    for slot in [9-10, 11-12, 13-14, 15-16, 16:30-17:30]:
  │     │      ├─ 查询飞书 busy_slots → 冲突继续
  │     │      ├─ 查询 DB existing_events → 冲突继续
  │     │      └─ 空闲 → return (start, end)
  │     │
  │     └─ fallback: 强制使用第一个 slot
  │
  ├─ 5. 创建飞书日历事件
  │     POST /open-apis/calendar/v4/calendars/{id}/events
  │
  └─ 6. 保存 CalendarEvent 记录到 DB
```

### 2.3 配置加密存储流程

```
 保存配置                  读取配置 (启动时)
 ────────                  ────────────────

 用户输入 API Key          ENCRYPTION_MASTER_PASSWORD
   │                        (环境变量)
   ▼                        │
 config.encrypt_if_sensitive  ▼
   │                        crypto.derive_key(pwd, salt)
   ├─ key in SENSITIVE_KEYS? │
   │  ├─ YES:                ▼
   │  │  crypto.encrypt()    load_config_from_db()
   │  │  ├─ os.urandom(12)   │
   │  │  ├─ AES-GCM seal     ├─ for each AppConfig row:
   │  │  └─ base64 token     │    if row.encrypted:
   │  │                      │      crypto.decrypt(token)
   │  │  stored_value=token   │    else:
   │  │  encrypted=1          │      直接使用 value
   │  │                      │
   │  └─ NO: 明文存储         └─ settings.apply_overrides()
   │
   └─ Upsert AppConfig(key, value, encrypted)
```

**密钥生命周期**：
```
ENCRYPTION_MASTER_PASSWORD (环境变量, 40+ 随机字符)
  └─ derive_key (PBKDF2-SHA256, 600k 迭代, 固定 salt)
      └─ _encryption_key (256-bit, 进程内存, 不持久化)
          ├─ encrypt()  → DB 存储 (base64 令牌)
          └─ decrypt()  ← DB 读取
```

## 四、LLM 调用策略

### 4.1 调用场景与策略

| 调用场景 | 模型使用 | 输入长度 | 策略 |
|----------|---------|---------|------|
| 元数据提取 | LLM (JSON mode) | 前 15000 字符 | 元数据在文档头部，截断即可 |
| 技术要求识别 | LLM (JSON mode) | 全文（最多 120000 字符） | 需完整上下文判断章节边界 |
| Excel 条目拆分 | LLM (JSON mode) | 章节段落+表格（最多 100000 字符） | 仅传入目标章节内容 |
| LLM 不可用时 | — | — | 关键词回退（正向/反向正则匹配） |

### 4.2 提示词设计原则

1. **结构化输出**：所有 prompt 强制 `response_format={"type": "json_object"}`
2. **低温度**：`temperature=0.05`，保证提取一致性
3. **宁缺毋滥**：不确定性内容宁可遗漏，不包含无关/商务内容
4. **原文保留**：技术条款提取时要求完整复制，不截断不概括

### 4.3 错误处理

```
LLM API 调用失败
│
├─ 网络错误/超时 → 返回 500 + 错误描述
├─ JSON 解析失败 → 返回空结果 + confidence=low
├─ API Key 未配置 → 返回 400 提示用户配置
└─ 内容过长 → 智能截断 (metadata:15k, sections:120k, entries:100k)
```

## 五、文件存储规范

### 5.1 上传文件

| 规则 | 值 |
|------|---|
| 路径 | `data/uploads/{uuid12}.{ext}` |
| 命名 | UUID 前缀 + 原扩展名 |
| 大小限制 | 500MB |
| 支持格式 | .pdf, .docx |
| 生命周期 | 项目删除时同步删除 |

### 5.2 生成文件

| 文件类型 | 命名规则 | 路径 |
|----------|---------|------|
| 信息摘要 | `{项目名称}信息V1.md` | `data/exports/` |
| 技术偏离表 | `{项目名称}_技术偏离表.xlsx` | `data/exports/` |
| 安全性 | 项目名称中的特殊字符替换为 `_` | |

### 5.3 Docker 持久化

```yaml
volumes:
  - ./data:/app/data     # SQLite + uploads + exports
  - ./app:/app/app       # 热重载 (开发模式)
```

## 六、安全架构

### 6.1 威胁模型

| 威胁 | 缓解措施 |
|------|---------|
| API Key 泄露 (源码) | 仅通过 .env 或加密 DB 存储，不硬编码 |
| API Key 泄露 (DB) | AES-256-GCM 加密，主密钥通过环境变量注入 |
| 外部 API 未授权访问 | Bearer Token 认证 (256 位熵) |
| 跨域攻击 | CORS 中间件 |
| 明文传输 | 建议配合反向代理启用 HTTPS |

### 6.2 安全边界
