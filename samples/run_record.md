## 六、最终重复率口径说明

### 计算过程（三步）

第一步：快速模式原始重复率

```
原始重复率 = (LCS 匹配字符数 / 招标文件总字符数) * 100
           = (500 / 888) * 100
           = 56.3%
```

第二步：AI 调整后重复率（LLM 真实调用）

```
AI 调整后重复率 = (LLM 判定的实际重复字符数 / 招标文件总字符数) * 100
               = (0 / 888) * 100
               = 0.0%
```

LLM 分类结果：
- 段 #0（600 字符）：LLM 判定为 compliance_response（合规应答）
- LLM 理由："重复内容主体为防火墙、终端安全系统的技术参数、功能指标及认证材料要求，投标文件以参数清单形式逐条确认并指向证明附件，属于必要的合规响应"
- LLM 将整段 600 字符全部标记为合规应答（因主体为技术参数响应）

第三步：人工修正后最终重复率

```
人工修正后重复率 = (修正后实际重复字符数 / 招标文件总字符数) * 100
                = (107 / 888) * 100
                = 12.0%
```

人工修正明细（4 处修正，共 107 字符从合规重分类为实际重复）：

| # | 文本区间 | 字符数 | 分类变更 | 理由 |
|---|---------|--------|---------|------|
| 1 | 0-22 | 23 | compliance → actual_dup | 文档标题核心名称被照搬（"某省级网络安全建设项目招标"） |
| 2 | 24-30 | 7 | compliance → actual_dup | "第一章 项目概述"章节标题逐字复制 |
| 3 | 32-96 | 65 | compliance → actual_dup | 项目背景叙述文本逐字照搬（"本项目旨在建设省级网络安全防护体系..."） |
| 4 | 97-113 | 12 | compliance → actual_dup | "第二章 技术要求"章节结构照搬 |

## 七、样本文本异常说明（IP00Gbps）

### 7.1 异常现象

匹配段文本中出现 "IP00Gbps" 字符串，该字符串不存在于原始输入文件中。

### 7.2 来源分析

来源：chunk 合并时的文本拼接产物。

匹配段由 3 个相邻 chunk（各 200 字符）合并而成，合并时直接拼接 chunk 文本。由于 chunk 间存在重叠区域，重叠部分的内容被重复拼接，导致 "支持 IPv6 协议栈"（上一个 chunk 末尾）和 "100Gbps"（下一个 chunk 开头）在拼接时形成 "IP00Gbps" 的视觉效果。

原始文件对应内容：
- tender 第12行：`- 支持 IPv6 协议栈`
- tender 第9行：`- 吞吐量不低于 100Gbps`

合并时两个 chunk 重叠区域的文本被拼接在一起，形成包含 "IP" 和 "00Gbps" 的连续字符串。

### 7.3 影响评估

| 指标 | 是否受影响 | 说明 |
|------|-----------|------|
| 原始重复率 56.3% | 不受影响 | LCS 算法基于原始文本计算，与匹配段展示文本无关 |
| AI 调整率 0.0% | 基本不受影响 | LLM 可理解上下文，拼接错误不影响分类判断 |
| 最终重复率 12.0% | 不受影响 | 人工修正基于原始文件内容，不依赖匹配段展示文本 |
| 报告可读性 | 轻微影响 | 匹配段展示文本存在拼接痕迹，但不影响数据准确性 |

### 7.4 结论

"IP00Gbps" 为匹配段文本拼接时的显示产物，非源文件错误，不影响重复率计算和 AI 分类结果。原始输入文件（tender_desensitized.txt、bid_A_desensitized.txt）内容干净，无此异常。
