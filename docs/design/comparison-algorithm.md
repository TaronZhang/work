# 文档比对算法设计

## 概述

DocDiff 使用 jieba 分词 + 字符级 LCS (最长公共子序列) 混合相似度算法，结合滑动窗口分块策略进行文档比对。

## 相似度计算

两段文本的相似度由两部分加权计算:

1. **词级相似度** (权重 0.6): 使用 jieba 对中文文本分词，然后用 SequenceMatcher 计算词序列的相似度
2. **字符级相似度** (权重 0.4): 直接用 SequenceMatcher 计算字符序列的相似度

最终相似度 = word_ratio * 0.6 + char_ratio * 0.4

## 分块策略

使用滑动窗口将文档切分为小块:

- 默认 chunk_size: 200 字符
- 默认 overlap: 50 字符
- 步长: chunk_size - overlap = 150 字符

每个块至少包含 min_match_length (15) 个非空白字符才参与比对。

## 匹配流程

1. 将两个文档分别分块
2. 对每个投标块，遍历所有招标块寻找最佳匹配
3. 长度差异超过 50% 的块对跳过 (性能优化)
4. 相似度超过阈值 (0.75) 的块对记录为原始匹配
5. 合并相邻且重叠的匹配段
6. 去重: 基于 bid_start 位置排序，重叠 >50% 时保留相似度更高的段
7. 取 Top 50 结果返回

## 大文件分片

当文件大于 10MB 或字符数超过 100,000 时触发自动分片:

### 拆分策略 (按优先级)

1. **章节拆分**: 沿 Heading1 标题边界拆分
2. **页码拆分**: 按页码均匀拆分
3. **等长拆分**: 按固定字符数拆分 (默认 50,000 字符/片，重叠 5,000 字符)

### 分片并发比对

使用 ThreadPoolExecutor (默认 4 线程) 并发处理分片对，超时 300 秒。

## AI 过滤

AI 模式下，先调用 LLM 对参考文档段落分类:

| 类别 | 说明 | 是否参与比对 |
|------|------|------------|
| format_requirement | 格式要求 | 否 |
| p2p_response | 点对点应答要求 | 否 |
| legal_clause | 法律条款 | 否 |
| scoring_criteria | 评分标准 | 否 |
| substantive | 实质性内容 | 是 |

仅 substantive 类型的段落参与最终比对。LLM 调用失败时保守策略: 全部标记为 substantive (不丢失内容)。
