### 5.4 真实项目与仓库样例的数字溯源

以甲公司投标文件为例，三步数字的来源和复算路径：

```
原始重复率 56.3%
    来源：LCS 算法确定性输出
    代码：src/comparator.py compare_documents()
    复算：python -m cli.main compare tender.txt bid_A.txt
    验证：matched_chars / total_tender_chars = 500/888 = 56.3%
          ↓
AI 调整后 33.8%（真实项目 e6bc128）
    来源：gpt-5.6-sol 分类（匹配段截断300字符）
    代码：src/ai_filter.py analyze_comparison_segments()
    复算：需使用 e6bc128 版本代码 + 相同截断逻辑
    验证：193合规 + 107重复 → 107/888 = 12.0%？ 不，33.8%是300字符截断后的结果
          ↓
AI 调整后 0.0%（当前修复版）
    来源：gpt-5.6-sol 分类（完整600字符段落）
    代码：当前版本 src/ai_filter.py + src/comparator.py（2000字符上限）
    复算：python -m cli.main compare tender.txt bid_A.txt --ai
    验证：600字符全被判定为合规应答 → 0/888 = 0.0%
          ↓
人工修正后 12.0%（最终采用）
    来源：售前技术工程师 + 售前技术经理 人工复核
    记录：samples/output/human_correction.json
    复算：107实际重复 / 888总字符 = 12.0%
    验证：4处修正明细，共107字符，理由可追溯
```

**结论**：原始重复率（56.3%）和最终人工修正率（12.0%）在真实项目和仓库样例中完全一致，可独立复算；AI 调整率因代码版本（匹配段截断长度）不同存在差异，但不影响最终评标采用的数字。

### 5.5 LLM 调用重试与可靠性控制

#### 代码实现状态

| 项 | 说明 |
|----|------|
| 自动重试/指数退避 | **未实现** |
| 代码位置 | `src/ai_filter.py` 的 `filter_tender_requirements()` 和 `analyze_comparison_segments()` |
| 错误处理方式 | try-except 单轮调用，失败时走降级逻辑 |
| 降级策略 | 事前过滤失败 → 全部段落标记为实质性内容（不过滤）；段分析失败 → 全部标记为实际重复（保守处理） |

#### 两处 LLM 调用的错误处理详情

**1. 事前过滤（`filter_tender_requirements`，第 183-203 行）**

```python
try:
    response = client.chat.completions.create(...)
    # 正常解析分类结果
except Exception as e:
    # 降级：所有段落标记为实质性内容（即不做过滤）
    for p in batch:
        all_annotations.append(AnnotatedParagraph(
            text=p,
            category='substantive',
            is_requirement=False,
            reason=f'LLM 调用失败: {str(e)}',
        ))
```

降级影响：重复率计算使用完整招标文件文本（未过滤），结果偏保守（重复率偏高），不影响安全性。

**2. 段级分析（`analyze_comparison_segments`，第 281-319 行）**

```python
try:
    response = client.chat.completions.create(...)
    # 正常解析分类结果
    if not batch_analyses:
        # JSON 解析失败 → 保守标记为实际重复
        for seg in batch:
            all_segment_analyses.append(SegmentAnalysis(
                classification='actual_duplication',
                reason='AI 返回解析失败，保守标记为实际重复',
            ))
except Exception as e:
    # 调用失败 → 保守标记为实际重复
    for seg in batch:
        all_segment_analyses.append(SegmentAnalysis(
            classification='actual_duplication',
            reason=f'AI 分析失败: {str(e)}',
        ))
```

降级影响：所有匹配段被标记为"实际重复"，AI 调整后重复率 = 原始重复率（不做任何扣除），结果偏保守。

#### 真实项目运行情况

| 项 | 详情 |
|----|------|
| 是否触发重试 | 否（无自动重试机制） |

| 真实项目是否需要人工介入 | 不需要（全部一次成功） |

#### 设计考量

未实现自动重试的原因：
1. 招投标审查场景对准确性要求高，宁可偏保守也不能漏报
2. 降级策略（失败则全部标记为重复）天然安全，不会漏过任何可疑重复
3. 运行时有人工值守，出现异常可快速手动介入
4. 单次比对耗时短（5-10分钟），重跑成本低

后续如需要自动重试能力，可在 `src/ai_filter.py` 中添加 `tenacity` 或手写指数退避逻辑，对 `client.chat.completions.create()` 进行包装。
