# 效果基线与复用范围说明

## 一、效果基线

### 1.1 基线场景：某省级网络安全建设项目投标文件审查

场景描述：4家供应商参与投标，每家提交3份文件（技术方案、商务方案、实施方案），共12份投标文件 + 1份招标文件，文件格式 .doc 和 .docx 混合，平均文件大小 8.5MB，总字符数约 56 万字。

### 1.2 生成前后对比

#### 传统人工方式（基线）

| 工作环节 | 耗时 | 人工修改量 | 备注 |
|---------|------|-----------|------|
| 文件阅读和理解 | 4小时 | - | 2人协作，重点审阅技术标 |
| 招标文件与投标文件逐对比对 | 4小时 | - | 4对（招标 vs 4家技术标），每对约1小时 |
| 投标文件两两互比 | 12小时 | - | 6组配对（4家技术标C(4,2)），每组约2小时 |
| 合规性判断（标注分类） | 8小时 | - | 逐段判断是否属于合规应答 |
| 报告编写和排版 | 2小时 | - | 4份单对报告 + 6份互比报告 + 1份汇总报告 |
| 评标汇报材料制作 | 4小时 | - | PPT 制作，含数据整理和图表 |
| 总计 | 44小时（约5.5个工作日，2人协作） | - | - |

#### 使用 bid_checker + chaitin-ppt-master 后

| 工作环节 | 耗时 | 人工修改量 | 备注 |
|---------|------|-----------|------|
| 文件上传和解析 | 5分钟 | 0 | 自动解析 .doc/.docx 格式 |
| 比对引擎计算（4对+6组） | 8分钟 | 0 | 含大文件自动拆分和并发比对 |

| AI 事后合规判定 | 15分钟 | 6段修正 | 186段中修正6段误判 |
| 人工复核 | 4小时 | 8段修正 | 复核AI分类和判定结果 |
| 报告生成 | 1分钟 | 0 | 自动生成 HTML + PDF 报告 |
| PPT 制作 | 1小时 | 20分钟微调 | chaitin-ppt-master 生成，人工调整版式 |
| 总计 | 5.5小时 | 8段修正 + 20分钟PPT微调 | - |

#### 效率提升

| 对比项 | 传统方式 | 工具辅助方式 | 提升 |
|--------|---------|-------------|------|
| 总耗时 | 44小时 | 5.5小时 | 提升8倍 |
| 人工修改量 | 全程人工 | 8段修正 + 20分钟微调 | 减少90% |
| 报告覆盖面 | 4份单对 + 6组互比 + 1份汇总 | 4份单对 + 6组互比 + 1份汇总 + 1份PPT | 覆盖面一致 |
| 最终使用状态 | 人工编写报告已归档 | HTML/PDF报告归档 + PPT已用于评标汇报 | 已用于实际评标决策 |

> 口径说明：上表 5.5 小时为完整工作流口径（含 PPT 制作 1 小时）。若仅统计 bid_checker 工具核心分析环节（解析+比对+AI+人工复核），耗时约 4.5 小时。详见 [版本说明 5.6 节](版本说明.md#56-真实项目运行时长统计口径)。

### 1.3 关键指标基线

以下指标可作为后续项目的效果基准线：

一、解析速度：平均每万字解析约 0.5 秒（含 .doc antiword 解析）

二、比对速度：平均每万字对比约 1.2 秒（jieba 分词 + LCS）

三、AI 分析速度：每批 10-15 段约 8-10 秒（LLM API 响应时间）

四、AI 分类准确率：段落分类 95.7%，合规判定 96.8%（首次运行，未经提示词优化）

五、人工复核比例：约 4.3% 的段落需要修正（8/186）

六、报告生成速度：单份 HTML + PDF 约 3 秒


## 二、复用范围

### 2.1 可直接复用的配置

| 配置项 | 当前值 | 复用建议 |
|--------|--------|---------|
| 比对阈值 | 0.75 | 适用于招投标场景，可根据项目调整 |
| chunk_size | 200 | 适合中文文档，英文文档建议调整为400 |
| 分片阈值 | 10MB / 10万字符 | 适用于大多数招投标文件 |
| AI temperature | 0.1 | 保证输出稳定性 |
| 批处理大小 | 10-15段/批 | 平衡API延迟和token消耗 |

### 2.2 可复用的业务场景

一、政府招投标文件审查：招标文件与投标文件比对、投标文件间相似度检测

二、企业采购文件审查：采购需求书与供应商方案比对

三、方案质量自查：提交投标前检查自身方案的重复度

四、合同条款审查：比对合同模板与实际签署文本的差异

五、学术文档查重预检：论文提交前自查重复率（非替代专业查重工具）

### 2.3 复用操作步骤

一、部署 agent-compose：在目标虚拟机部署 agent-compose（需 >= v2608.4.0）

二、构建 guest 镜像：使用 Dockerfile.agent 构建 bid-checker-guest 镜像

三、配置 agent-compose.yml：在 agent-compose 项目配置中添加 bid-checker Agent

四、配置 LLM：在 docker-compose.yml 中配置公司 AI Gateway 地址和模型名

五、上传文档：通过 agent-compose Web UI 上传待比对文件至 /workspace/ 目录

六、执行比对：在聊天框输入自然语言指令，Agent 自动执行比对命令

### 2.5 后续优化方向

一、增加 OCR 支持：当前 .pdf 格式仅支持文本型PDF，扫描型PDF需要OCR能力

二、跨文件模板复用检测：当前AI分析仅对单对比对结果进行判定，后续增加跨文件分析

三、批量自动化：支持定时任务自动比对新增文件

四、历史数据对比：支持与历史项目的比对结果进行趋势分析

五、提示词优化：根据人工复核反馈，优化AI分类和判定提示词，目标准确率提升至98%以上
