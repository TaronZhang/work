# 调整后重复率口径说明

## 计算公式

调整后重复率 = (实际重复字符数 / 招标文件总字符数) * 100

其中：
- 实际重复字符数 = 所有被 AI 分类为 actual_duplication 的匹配段 tender_text 长度之和
- 合规应答字符数 = 所有被 AI 分类为 compliance_response 的匹配段 tender_text 长度之和
- 招标文件总字符数 = 比对时招标文件的全文长度（来自 ComparisonResult.total_tender_chars）

## 口径定义

一、原始重复率（快速模式）
- 计算方式：(LCS 匹配字符数 / 招标文件总字符数) * 100
- 不区分合规应答与实际重复
- 入口：src/comparator.py compare_documents()

二、调整后重复率（AI 模式）
- 计算方式：(实际重复字符数 / 招标文件总字符数) * 100
- 排除合规应答部分（技术参数响应、资质声明等必要重复）
- 入口：src/ai_filter.py analyze_comparison_segments() 第 321-339 行
- 计算使用完整段落文本长度，非发送给 LLM 的 500 字截断版本

## 边界处理

### 场景一：匹配段文本被截断

问题：发送给 LLM 的段文本被截断为 500 字，但计算调整后重复率时需要使用完整段落文本。

处理方式：
- LLM 调用时截断：seg.get("tender_text", "")[:500]（src/ai_filter.py 第 277 行）
- 计算时使用完整文本：sa.tender_text（来自原始 batch 中的 seg.get('tender_text')）
- _parse_segment_analysis() 从原始 batch 中查找完整文本，不使用截断版本

验证：段文本长度 = len(sa.tender_text) = 原始段落长度（非 500）

### 场景二：LLM 返回缺项

问题：LLM 返回的分析结果数量少于输入段落数量。

处理方式（src/ai_filter.py 第 401-454 行）：
- 按 segment_id 匹配，找不到时按索引位置匹配
- 仍未匹配的段落，标记为 actual_duplication，理由为"LLM 未返回该段分析，保守标记为实际重复"
- 确保输出数量 = 输入数量，不遗漏

### 场景三：JSON 解析失败

问题：LLM 返回的内容不是有效 JSON 或无法匹配到数组。

处理方式（src/ai_filter.py 第 294-305 行）：
- _parse_segment_analysis() 返回空列表
- 调用方检测空列表，将所有段落标记为 actual_duplication
- 理由为"AI 返回解析失败，保守标记为实际重复"
- 调整后重复率 = 原始重复率（保守策略，不降低重复率）

### 场景四：LLM 调用异常

问题：LLM API 调用失败（网络错误、认证错误等）。

处理方式（src/ai_filter.py 第 308-319 行）：
- 捕获异常，将该批所有段落标记为 actual_duplication
- 理由为"AI 分析失败: {错误信息}"
- 调整后重复率 = 原始重复率（保守策略）

### 场景五：段落重叠

问题：多个匹配段的 tender_text 存在内容重叠，导致字符数重复计算。

说明：
- 比对算法（LCS + jieba 分词）生成的匹配段基于文本偏移量（tender_start, tender_end）
- 正常情况下匹配段不重叠，但极端情况下可能出现部分重叠
- 当前实现按段落文本长度累加，不做去重
- 如需精确去重，可按 (tender_start, tender_end) 区间合并后计算

### 场景六：空分析数组

问题：比对结果中 segments 为空（无匹配段）。

处理方式（src/ai_filter.py 第 251-261 行）：
- 直接返回 ComparisonAnalysis，adjusted_percentage = original_percentage
- 不调用 LLM，summary 为"无匹配段落，无需 AI 分析"

## 人工复核标准

一、复核人角色：售前技术工程师（初级）+ 售前技术经理（审核）

二、复核步骤：
1. 检查 AI 分类是否正确（合规应答 vs 实际重复）
2. 检查 AI 判定理由是否合理
3. 对混合内容段落（含合规应答和实际重复）进行拆分修正
4. 确认调整后重复率 = (修正后实际重复字符 / 招标文件总字符) * 100

三、修正记录：
- 记录修正前后的分类变化
- 记录修正原因
- 最终口径以人工修正后为准
